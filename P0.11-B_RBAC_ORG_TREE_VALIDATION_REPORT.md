## 3. API SECURITY VALIDATION (Verified via `test_p0_rbac`)

We have strictly validated that security is enforced at the **API layer**, not just hidden in the frontend UI. The RBAC regression test suite confirms:

✅ **Cross-Employee Data Isolation (IDOR Prevented):**
- *Assertion Passed:* `Employee -> own data -> ALLOW`
- *Assertion Passed:* `Employee -> another employee -> DENY (HTTP 403)`
- Worker/Employee requests to calculate/approve API endpoints are actively rejected.

✅ **Manager Data Scope Isolation:**
- *Assertion Passed:* `Manager A -> Dept A -> READ ALLOW`
- *Assertion Passed:* `Manager A -> Dept B -> READ DENY (HTTP 403)`
- Managers cannot globally approve payroll.

✅ **HR Execution Constraints:**
- HR role can successfully invoke `PAYROLL_CALCULATE` for the company.
- *Assertion Passed:* `HR gets 403 on Publish` (Ensures segregation of duties: HR calculates, BOD publishes).

✅ **BOD / Admin Authority:**
- BOD successfully authenticated to invoke `PAYROLL_PUBLISH`.
