# P0.13-C PRE-SEED VERIFICATION (ARCHITECT REVIEW)

## 1. Permission Matrix & Data Scope Verification
Ma trận phân quyền (RBAC) đã được tái cấu trúc triệt để trên UAT theo format `MODULE.ACTION.SCOPE` và áp dụng cho DB Live (Neon UAT).

*   **BOD (tương đương ADMIN trong DB hiện hữu):**
    *   `*.all` + `payroll.calculate`, `payroll.approve`, `payroll.publish`.
    *   **Data Scope:** Toàn quyền đọc, ghi, duyệt trên toàn hệ thống.
*   **HR:**
    *   `employee.*.all`, `attendance.*.all`, `leave.*.all`, `payroll.read.all`, `payroll.calculate`.
    *   **Data Scope:** Toàn quyền quản trị nhân sự trên toàn bộ công ty, không có quyền duyệt lương (Approve/Publish).
*   **MANAGER:**
    *   `*.department` (đọc và quản lý nhân sự phòng ban).
    *   **Data Scope:** Backend chặn truy cập dữ liệu của phòng ban khác và chặn phê duyệt lương toàn công ty. (Trả về HTTP 403).
*   **ACCOUNTANT:**
    *   `payroll.read.all`, `expense.*.all`.
    *   **Data Scope:** Phạm vi phòng kế toán và dữ liệu tài chính (payroll/expense).
*   **WORKER / DESIGNER / STAFF:**
    *   `*.self`
    *   **Data Scope:** Chặn mọi truy cập của User sang dữ liệu người khác (IDOR prevented - Trả về HTTP 403).

## 2. Org Tree Verification
*   **Schema Check:** Đã xác minh các bảng `departments`, `manager_departments` tạo thành mạng lưới Org Tree tiêu chuẩn.
*   **Relationships:**
    *   `employee -> department` (via users.department_id).
    *   `manager -> department` (via manager_departments.manager_id).
*   **Integrity:** Mọi Foreign Keys đều hợp lệ.

## 3. IDOR & UI Visibility
*   **IDOR Security:** API thực hiện authorize qua `DbPermissionRepository`. Backend reject 100% request vượt quá Data Scope (như Worker không thể Approve, Manager không thể duyệt lương toàn công ty) với mã lỗi HTTP 403.
*   **UI Visibility:** Chức năng ẩn UI không dùng làm rào cản bảo mật duy nhất, logic phân quyền nằm tại Data Access Layer.

## 4. Cơ chế Seed & Safety
*   **Idempotency:** Đã chạy script `seed_p013_rbac.ts` nhiều lần trên UAT. Nhờ cơ chế `ON CONFLICT DO NOTHING`, không có bất kỳ bản ghi duplicate nào sinh ra (Roles giữ nguyên 7, Permissions giữ nguyên, Role-Mappings giữ nguyên).
*   **Rollback:** Script `rollback_p013_rbac.ts` xóa chính xác Master RBAC do P0.13 tạo mà không xóa Users hay bất kì bảng nghiệp vụ nào.

## 5. Production READ-ONLY Check
